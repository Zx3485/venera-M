### 3.1 配色锁定（`e4b565f`）

**外观页的 Theme Color 已移除**。杂志版只有一套配色：

| 角色 | 值 | 用途 |
|---|---|---|
| `kInkSeed` `#8A8F98` | 墨灰 | 中性色（surface / onSurface / outline） |
| `kRustSeed` `#A4522C` | 钢红 | `primary` / `secondary`（交互强调） |
| `kRustColor(context)` | 钢红 | 装饰性强调（报头圆点、章节选中、评分） |

实现方式：`getTheme(Brightness)` 里 `primaryKey` / `secondaryKey` 都用 `kRustSeed`，
`tertiaryKey` 用 `kInkSeed`。

**为什么不逐个改那 35 处 `colorScheme.primary`：**
它们集中在按钮、Tab 选中、下拉箭头、收藏态、章节选中——正好都是「交互强调」语义。
换种子后自动变钢红，不用改引用；而且明暗两套主题各自生成合适明度，
比硬编码 `kRustColor` 更稳（后者在暗色下偏暗）。

**同时删掉了 `DynamicColorBuilder`**：它是「跟随系统壁纸取色」，本质是主题色的
另一个来源，留着同样会让版面跑色。`dynamic_color` 的 import 也已移除。

> 设置键 `color` **仍保留**在 `appdata.dart` 默认值里（加了废弃注释）。
> 删掉会让旧同步数据走进「未定义」分支，反而更容易出问题。

#### 6.1 清晰度修复（`12b9421`）

用户反馈桌面图标发虚。查到两个根因，都在生成脚本里：

**① 自适应图标分辨率不足（主因）**

Android 自适应图标的前景/背景层，**实际渲染尺寸是 108dp**，不是 launcher 的 48dp。
xxxhdpi 下 108dp = 432px，而旧脚本只出 192px → 系统拉伸 2.25 倍 → 边缘糊。

现在按 `px * 108 / 48` 出图：

| density | launcher (48dp) | 自适应层 (108dp) |
|---|---|---|
| mdpi | 48 | **108** |
| hdpi | 72 | **162** |
| xhdpi | 96 | **216** |
| xxhdpi | 144 | **324** |
| xxxhdpi | 192 | **432** |

**② 前景 M 的尺寸（连错三轮，最终 74%）**

自适应图标 108dp 画布中**只有中间 72dp 保证可见**（安全区 66.7%）。

这里犯过一个方向性错误：**以为安全区是「必须填满」的目标**。
实际它只是「保证不被裁」的上限，图标设计惯例是图形占安全区 **74~80%**。

三轮调整记录：

| 版本 | 参数 | 占安全区 | 结果 |
|---|---|---|---|
| `12b9421` | `FILL=1.20` | 97% | ❌ 竖笔被启动器裁掉，糊在边缘 |
| `fa058a3` | `FILL=1.06` | 85% | ⚠️ 不裁了，但仍偏大 |
| `dc2373a` | `FILL=0.90` | **74%** | ✅ 留白 27dp，用户确认「合适了」 |

> 注意：48dp 的 launcher 图 / iOS / macOS 用 `scale=1.0`。
> 那些平台**没有安全区裁剪**，保持「M 占画布 53%」的原比例。

**③ 补上 `ic_launcher_round.png`**（圆形启动器用，原来缺失），
并在 `AndroidManifest.xml` 加 `android:roundIcon="@mipmap/ic_launcher_round"`。

**④ 发虚的真正原因：位图被 LANCZOS 处理了两遍**

旧 `draw_m` 的实现是：

```
draw_m_raw(1024) → resize(放大 1.2x) → crop → resize(目标尺寸)
                     ↑ 第一次重采样      ↑ 第二次重采样
```

边缘本来只有几像素的过渡带，反复插值就被抹开了。

现在改成**几何参数化**：把缩放系数直接乘进 `stroke` / `box_w` / `box_h`，
按「目标尺寸 × 8」一次绘制，最后只 LANCZOS 缩小一次。
**全程单次绘制、单次降采样。**

实测过渡带（越低越锐）：`xxxhdpi 2.52%`、`xxhdpi 3.16%`、`mdpi 8.76%`
（mdpi 因为只有 108px，笔画本身才 5px 宽，过渡带占比自然高，属正常）。

**验证数据**（可复现）：

```
xxxhdpi ic_launcher_foreground.png  432×432  占安全区 74%，留白 27.2dp
各密度占比                            74~81%（低密度取整偏高，正常）
圆形 / 圆角 / 方形三种启动器遮罩        M 均不贴边
25 个 Android 图标文件齐全，尺寸全部对齐 dp 规范
```

**脚本关键参数**（`.tools/build_icon.py`）：

```
FILL = 0.90          # 自适应前景的缩放系数（几何参数，非事后拉伸）
SS = 8               # 超采样倍数，抗锯齿靠它
ADAPTIVE_DP = 108    # 自适应图标画布 dp
```

> 改 `FILL` 只需一秒就能重出全部 60 个图标。
> 标定方法：`draw_m(432, None, fill_ratio=X)` 后量 alpha 通道 bbox 宽度 ÷ 432 × 108 ÷ 72。

## 三、必须遵守的规则

### 禁止修改（会破坏功能或数据）

| 项目 | 原因 |
|---|---|
| `pubspec.yaml` 的 `name: venera` | Dart 包名，200+ 处 `package:venera/` 依赖 |
| `.venera` 同步文件扩展名 | 云端已有备份都是这个后缀，改了读不出来 |
| `MethodChannel("venera/...")` | 改了需同步 C++ 端，否则剪贴板/音量/文件选择全失效 |
| `applicationId com.github.wgh136.venera` | 会被当新 App 安装，手机里的数据和设置不会带过去 |

### 技术禁忌

**绝对不要用 PowerShell 的 `Set-Content` / `-replace` 批量改文件。**

2026-11-15 踩过两次：

1. `-replace` 处理中文注释时破坏编码，注释换行被吞、中文全变乱码，
   一次制造了 103 条编译错误，最后靠 `git checkout` 整体回滚才救回来。
2. 同一天晚上对 `.tools/build_icon.py` 用 `Set-Content -Encoding UTF8 -NoNewline`
   做简单字符串替换，结果**中文全变乱码 + 换行被吞 + 缩进错乱**，
   Python 直接 `IndentationError`，只能整篇重写。

**批量改代码一律用 `edit` 工具**（精确文本匹配，不碰编码，不碰行尾）。
纯 ASCII 的正则批量替换（如 `BorderRadius.circular(N)`）可以用 **Python 脚本**
——Python 显式用 `encoding='utf-8'` 读写，不会像 PowerShell 那样擅自转编码；
跑完必须立刻 `dart analyze`。

**⚠ 编码事故的破坏范围会被低估，必须主动扫描。**

`dart analyze` **查不出注释里的乱码**——只坏在 `//` 里的字，编译器根本不看。
所以事故发生后，以为「回滚了 3 个文件就没事了」是错的：
`chapters.dart` 也被 `-replace` 伤了 14 行中文注释，直到 2026-11-18
用户截图看到「1 鈫?366」才暴露，潜伏了 3 天。

**每次批量操作后，除了 `dart analyze`，必须扫一遍乱码特征：**

```python
import re
BAD = re.compile(r"[\uFFFD鈫鈥鈩锛鐨鍜鏄娴鑺犵粍缁撴瀯]")
for p in pathlib.Path("lib").rglob("*.dart"):
    text = p.read_bytes().decode("utf-8")
    for i, line in enumerate(text.split("\n"), 1):
        if BAD.search(line):
            print(f"{p}:{i}: {line.strip()}")
```

**这类损坏不可逆**：原字节在误解码成 `?` 时就永久丢了，
不能用「GBK 编码回 UTF-8」还原。
唯一的救法是从**损坏发生前的提交**里按行号取回原文
（`git show <good-rev>:<path>`），前提是那个版本还在。

**预防**：UI 文案里不要用 `→` `·` `「」` 这类非 ASCII 符号做拼接，
用 ASCII 替代（`-` `|` 之类）或直接用图标（`Icons.arrow_forward`）。
上游原始版本就是用 `Icon` 而不是字符，是我在 `ca2d9a8` 引入 `→` 才埋下这颗雷。

### 已知的坑

1. `ts.s11` 不存在，`ts` 最小是 `s12`
2. `_GreetHeader` 由外层 `SliverToBoxAdapter` 包裹，**内部必须返回 Box 组件**，
   返回 Sliver 会在运行时崩溃（`RenderSliverToBoxAdapter` 类型不匹配），analyze 查不出
3. 报头不要再加搜索图标——`search` 是独立的可开关板块，默认开启，会变成两个搜索入口
4. 日期 weekday 逻辑**没有 bug**（2026-11-15 确为周日），不要动
5. `editorial.dart` 里的组件都是 `part of components.dart`，只能在有 provider 作用域时用；
   独立文件（如 `rich_comment_content.dart`）里调不到 `kCorner`
6. `RadioListTile` 换成 `EditorialRow` + `Radio` 时要手动把整行点击接回去
   （`RadioGroup.maybeOf<T>(context)?.onChanged`）
7. 批量改圆角后用 `analyze` 抓 `kCorner isn't defined` 是最快找出「没有 context 作用域」的办法
