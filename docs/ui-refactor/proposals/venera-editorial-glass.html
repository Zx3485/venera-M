按主人说的组合：B 杂志的排版骨架（报头、编号目录、衬线标题、直角封面、全大写小字标） ＋ A 的椭圆玻璃悬浮底栏。

底栏是重点：它不贴边、不占位，是浮在内容之上的一枚胶囊。内容可以从它后面穿过去并被磨砂模糊。 选中态我改成了「锈红底 + 下方一道短横线」——底下的短横线呼应 B 的杂志排版语言，而不是 A 那种圆点。

这套组合具体怎么落地

  • 底栏改造是「换皮」不是重写。现有 _NaviMainViewState.build 里那段 Stack + Positioned.fill + padding.bottom += 58 已经是悬浮结构了，只需要：把 Container 换成带 borderRadius: 999 的胶囊、左右留 12–16 边距、去掉顶边 hairline 换成四周描边、加阴影。
  • 选中态从「圆点」改成「短横线」——这条线是 B 的语言（B 的顶栏选中态也是短横线），比 A 的圆点更协调。
  • 底栏要带文字标签了。现在是 纯图标（_SingleBottomNaviWidget 里只有 Icon，没有 Text）。改成图标+8px 小字，高度 44。这是这次唯一动到交互语义的地方。
  • 安全区余量：现在是 +58，胶囊版需要改成 胶囊高 56 + 底部间距 18 = 约 74。同时 floatingBottomBarInset(context) 也要跟着改，否则 FAB 会被压住一半。
  • 玻璃开关必须保留。关掉磨砂时要退回「实色胶囊 + 描边」，不能变成透明看不见。

我发现的三个真实风险

  • 侧栏有 3 种形态、2 个断点。600 和 1300 会切换折叠侧栏 / 全侧栏 / 底栏，宽屏下底栏根本不存在。胶囊版只需要管「底栏」那一档，但别把侧栏的 72/224 高度逻辑带坏。
  • _SingleBottomNaviWidget 里那个 width: 32 + value*32 动画是为「只有图标」设计的。加了文字之后这个宽度会撑爆 57px 的格子，必须一起改。
  • B 方向依赖衬线字体，而 pubspec.yaml 里 fonts: 到现在还是注释状态。不打包 Noto Serif SC 的话，这套排版在没装该字体的机器上会静默退化成无衬线，杂志感直接没了一半。这是需要主人拍板的：要不要为此增加 2–5MB 包体积。
